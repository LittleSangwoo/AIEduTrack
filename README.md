## 📋 Описание кейса

Система анализирует профиль ГГС (должность, ИОГВ) и его историю прохождения программ повышения квалификации (ППК) и электронных курсов (ЭК), после чего с помощью нескольких ИИ-агентов формирует персональные рекомендации к обучению — с учётом уже пройденного материала и опыта коллег на аналогичных должностях.

Проект подготовлен как кейс для Корпоративного университета Санкт-Петербурга.

## ✨ Ключевые особенности

* **Две роли работы:** отдельный интерфейс для методиста (загрузка данных, конструктор траектории, аналитика) и отдельный для ГГС (получение своей персональной траектории).
* **Мультиагентная архитектура:** запрос к нейросети проходит через цепочку специализированных агентов — анализ контекста, генерация черновика, валидация и обоснование, — а не единый монолитный промпт.
* **Защита от галлюцинаций:** каждая рекомендация сверяется с реальным каталогом курсов; то, чего в каталоге нет, а также уже пройденные курсы — автоматически отсеиваются.
* **Три группы нейросетей:** отечественные (GigaChat, YandexGPT), зарубежные (Groq) и локальные (Ollama) — с возможностью переключения без изменения кода.
* **Гибкий приём данных:** реестр курсов и история обучения — Excel/CSV с автоопределением заголовков; буклет программ ППК — PDF; поддержка JSON.
* **Работа без базы данных:** данные хранятся в памяти приложения на время его работы — это осознанное архитектурное решение, упрощающее развёртывание для кейса такого масштаба.
* **Экспорт результата:** готовая траектория выгружается в Excel, Word или JSON.
* **Тёмная/светлая тема** интерфейса с сохранением выбора пользователя.

## 🛠 Технологический стек

* **Язык и фреймворк:** C#, ASP.NET Core MVC (.NET 10.0).
* **Frontend:** Razor Views, HTML5, CSS3 (кастомные CSS-переменные под обе темы), Bootstrap 5, ванильный JavaScript.
* **Работа с Excel:** библиотека `ClosedXML` — чтение реестра курсов и истории обучения, формирование отчётов.
* **Работа с PDF:** библиотека `PdfPig` (UglyToad.PdfPig) — извлечение карточек программ ППК из буклета через анализ координат слов на странице (двухколоночная вёрстка не восстанавливается стандартным построчным чтением текста).
* **Экспорт в Word:** `DocumentFormat.OpenXml`.
* **AI Engine (LLM Layer):** единый OpenAI-совместимый клиент для большинства провайдеров + отдельный клиент под протокол GigaChat (OAuth-токен, специфика TLS).
* **Оркестрация:** Docker, Docker Compose.
* **Хранилище конфигурации провайдеров:** файл `llm_providers.json` (не входит в репозиторий — хранится локально у каждого разработчика).

## 🧩 Архитектура ИИ-агентов

Формирование траектории проходит по конвейеру из четырёх агентов, управляемых `TrajectoryOrchestrator`:

1. **ContextAnalyzerAgent** — собирает текстовый контекст: профиль ГГС, его личную историю обучения (пройдено/не пройдено), а также паттерн — какие курсы чаще всего успешно проходят коллеги с той же должностью в том же ведомстве. Это позволяет давать осмысленные рекомендации даже новому сотруднику, у которого личной истории ещё нет.
2. **TrajectoryCuratorAgent** — отправляет собранный контекст и урезанный каталог курсов в выбранную нейросеть с жёстким системным промптом, требующим строго структурированный JSON-ответ.
3. **ValidatorAgent** — сверяет каждый предложенный курс с реальным каталогом (защита от выдуманных нейросетью курсов), исключает уже пройденные программы и дубликаты внутри самого маршрута.
4. **ExplainerAgent** — для каждого прошедшего валидацию курса формирует персональное текстовое обоснование, почему он рекомендован именно этому сотруднику.

## ⚙️ Системные требования

Требования зависят от выбранного режима работы нейросети.

### Вариант А: внешние API (Groq, GigaChat, YandexGPT)
Вычисления происходят на стороне провайдера.
* **CPU:** любой современный 2-ядерный процессор.
* **RAM:** от 4 ГБ.
* **Сеть:** стабильное подключение к интернету, доступ к внешним API соответствующих провайдеров.

### Вариант Б: локальная нейросеть (Ollama + Llama 3)
Данные не покидают контур организации, но требуются дополнительные вычислительные мощности для инференса.
* **CPU:** современный 4+ядерный процессор.
* **RAM:** от 16 ГБ.
* **GPU:** желательно (ускоряет генерацию), но не обязательно — Ollama умеет работать и на CPU, просто медленнее.
* **Диск:** минимум 10 ГБ свободного места под образ Ollama и веса модели.

## 🚀 Развёртывание (инструкция для администратора)

Список подключённых нейросетей и их ключи хранятся в файле `AIEduTrack/llm_providers.json`. **Этот файл не входит в репозиторий** — при первом запуске приложение создаёт его само со значениями-заглушками; реальные ключи провайдеров указываются через раздел «Шлюзы ИИ» в самом интерфейсе после запуска.

### Способ 1. Docker Compose (рекомендуемый)

Убедитесь, что установлен Docker Desktop.

```bash
# 1. Клонирование репозитория
git clone https://github.com/LittleSangwoo/AIEduTrack.git

# 2. Переход в директорию с docker-compose.yml
cd AIEduTrack

# 3. Сборка и запуск контейнеров
docker-compose up -d --build

# 4. (Опционально, для локальной модели) загрузка весов Llama 3
docker exec -it aieduTrack-ollama-server-1 ollama run llama3
```

> 💡 Точное имя контейнера Ollama может отличаться — уточните его командой `docker ps` после запуска `docker-compose up`.

### Способ 2. Локально (Visual Studio)

Используется для разработки и отладки.

1. Откройте `AIEduTrack.sln` в Visual Studio.
2. Восстановите NuGet-пакеты (`ClosedXML`, `PdfPig`, `DocumentFormat.OpenXml`).
3. Запустите проект профилем `https`.
4. При первом запуске в корне проекта автоматически создастся `llm_providers.json` со значениями по умолчанию — впишите реальные ключи через раздел «Шлюзы ИИ» в интерфейсе.

### Способ 3. Командная строка

Как у любого стандартного ASP.NET Core приложения:

```bash
dotnet AIEduTrack.dll
```

## 📖 Руководство пользователя

При запуске приложение открывает экран выбора роли — **методист** или **ГГС**.

### Роль «Методист»

1. **Загрузка данных.** В разделе «Конструктор» загрузите три файла:
   * История обучения ГГС (.xlsx / .csv) — обязательно;
   * Реестр электронных курсов (.xlsx / .csv) — обязательно;
   * Буклет программ ППК (.pdf) — необязательно, но без него в каталоге останутся только электронные курсы.
2. **Выбор сотрудника.** После загрузки данных в выпадающем списке появятся реальные ГГС с их должностями; при выборе отображается карточка с уже пройденными и не пройденными курсами.
3. **Формирование траектории.** Выберите ИИ-движок (отечественный, зарубежный или локальный) и нажмите «Сформировать траекторию» — система соберёт контекст, обратится к нейросети и покажет готовый маршрут с обоснованием по каждому курсу.
4. **Экспорт.** Над готовым маршрутом доступны кнопки скачивания в Excel, Word и JSON.
5. **Аналитика.** На отдельной странице можно прогнать группу тестовых профилей через все подключённые провайдеры и получить сравнительный Excel-отчёт (время генерации, число отфильтрованных ошибок, состав рекомендаций) — используется для сравнения нейросетей на защите проекта.
6. **Шлюзы ИИ.** Раздел настроек провайдеров — добавление, редактирование и удаление подключений к нейросетям.

### Роль «ГГС»

1. **У меня есть ID / ФИО.** Введите свой идентификатор так же, как он указан в загруженной методистом истории обучения (система сразу подскажет, найден ли профиль).
2. **Я новый ГГС.** Если истории обучения ещё нет, выберите свою должность и ведомство из списка (составлен из уже загруженных данных) — рекомендации в этом случае строятся на основе опыта коллег на аналогичной должности.
3. Выберите ИИ-движок и нажмите «Получить мою траекторию».
4. Готовый маршрут можно скачать в Excel, Word или JSON.

## 🧠 Поддерживаемые модели ИИ

Проект использует минимум три категории нейросетей, как того требует кейс.

### Отечественные
* **GigaChat (Сбер)** — собственный протокол авторизации через OAuth-токен; для работы TLS/SSL с российскими провайдерами в проект встроены сертификаты Национального удостоверяющего центра Минцифры РФ.
* **YandexGPT** — доступ через OpenAI-совместимый эндпоинт Yandex Cloud AI Studio.

### Зарубежные
* **Groq** — быстрый инференс открытых моделей через OpenAI-совместимый API.

### Локальные
* **Ollama (Llama 3)** — модель разворачивается в изолированном контуре без доступа в интернет; вся обработка данных происходит на инфраструктуре организации.

## 🔧 Устранение типичных неполадок

| Проблема | Возможная причина | Решение |
| :--- | :--- | :--- |
| **403 Forbidden от нейросети** | У API-ключа нет нужного разрешения (scope), либо не совпадает ID папки/аккаунта провайдера. | Проверьте настройки ключа в личном кабинете провайдера — убедитесь, что у него есть право на обращение к соответствующему сервису генерации. |
| **«Каталог курсов пуст»** | Методист ещё не загрузил файлы реестра и истории обучения. | Загрузите оба обязательных файла в разделе «Конструктор» → «Обновление данных». |
| **Часть курсов из истории не находит соответствия в каталоге** | Загружен только реестр электронных курсов без буклета программ ППК. | Дополнительно загрузите PDF-буклет — он служит источником карточек ППК. |
| **Пользователь не найден** | ID/ФИО введены не так, как в исходном файле истории обучения. | Сверьте точное написание в исходном файле; поиск регистронезависим, но требует совпадения самого текста. |
| **Не сохраняются настройки провайдера** | Проблема с правами доступа к `llm_providers.json`. | Убедитесь, что процесс приложения имеет права на запись в свою рабочую директорию. |

## 🗂 Структура проекта (основное)

```
AIEduTrack/
├── Controllers/       — Home (выбор роли), Methodist, Ggs, Settings, Dashboard
├── Data/               — парсеры (Excel/CSV/PDF), in-memory репозиторий
├── Models/             — сущности (UserProfile, Course) и DTO
├── Services/
│   ├── Agents/         — ContextAnalyzerAgent, TrajectoryCuratorAgent, ValidatorAgent, ExplainerAgent
│   ├── LLM/             — клиенты провайдеров, фабрика, настройки
│   └── Report/          — экспорт траектории и бенчмарк-отчёт
├── Views/               — Razor-представления по ролям
├── Certificates/         — сертификаты НУЦ Минцифры РФ (для GigaChat)
├── Dockerfile
└── docker-compose.yml
```

## ⚠️ Известные ограничения демо-версии

* Список сотрудников в интерфейсе методиста виден полностью — в проде для реального контура это стоит закрыть авторизацией, чтобы не раскрывать персональные данные всех ГГС.
* Данные хранятся в памяти приложения и не переживают перезапуск — для промышленной эксплуатации потребуется персистентное хранилище.
